# sku-manager · 采购价与产品档案

把散落在 Excel / PDF 合同里的采购价、起订量、产品规格,抽成一个能搜的本地库。
报价时不用再翻合同,也不用去问采购。

**数据完全存在本机**,不上传任何服务器。GitHub 只用来分发新版本。

---

## 它能做什么

- **合同自动解析** —— 拖入 Excel / PDF,自动认出货号、采购价、起订量、品名,
  连合同下方的材质/配件/包装要求也会归到对应型号名下
- **产品(SPU)/ 货号(SKU)两层** —— 一个产品下挂多个尺寸,列表看产品,点开比参数
- **自定义参数** —— 夹紧力、开口、功率、内径……参数名自己定,不写死行业
- **供应商档案** —— 联系人、工厂所在地、主营类目(类目可点击直接筛货)
- **调价历史** —— 每个价格都能追到来自哪份合同、哪天改的
- **悬浮问一句** —— 页面右下角的聊天按钮,点开直接问价格、比价、查最近调价,
  也能直接交代活儿(「帮我整理一下供应商」);数字全部来自真实查询,
  改动全程记流水、随时一键回退;不配 AI 也能用(自动降级为关键词检索)
- **表格导出** —— 聊天查到的结果一键导出 **XLSX / CSV**,报价表直接带走
- **图形化文件夹选择器** —— 填路径不用手敲:盘符、常用位置、新建文件夹点着选
- **整库导出/导入** —— 一个 `.db` 文件含全部数据和图片,换设备直接搬
- **AI 兜底解析(可选)** —— 规则认不出的合同交给模型,本地或云端二选一

## 安装

需要 **Node.js 20 或更高**。没装的话去 [nodejs.org](https://nodejs.org) 下 LTS 版。

### Windows

1. 从 [Releases](https://github.com/Drsakura/sku-manager/releases) 下载最新的
   `sku-manager-<版本>.zip`,解压到任意目录(建议 `D:\sku-manager`)
2. 在该目录打开终端(地址栏输入 `cmd` 回车),执行:
   ```
   npm install
   ```
3. 双击 **`start.bat`** 启动
4. 浏览器打开 http://localhost:3300

### macOS

1. 下载并解压同一个 zip(建议放 `~/sku-manager`)
2. 终端执行:
   ```bash
   cd ~/sku-manager
   npm install
   ```
3. 双击 **`start.command`** 启动

   > 首次双击若提示"无法打开",在终端执行一次
   > `chmod +x start.command`;若提示"来自身份不明的开发者",
   > 在「系统设置 → 隐私与安全性」里点"仍要打开"。

4. 浏览器打开 http://localhost:3300

> **不要把 Windows 的 `node_modules` 拷到 Mac**(反之亦然)。
> 里面的 `better-sqlite3` 等是按平台编译的二进制,必须在各自机器上
> `npm install` 重新生成。

停止服务:终端窗口按 `Ctrl + C`(Mac 上是 `Control + C`)。

## 日常使用

### 导入合同

「合同导入」页有两种方式:

| 方式 | 说明 |
|---|---|
| **拖入文件** | 把 Excel / PDF 拖进框里,解析完文件会归档到 `archive/` |
| **扫描文件夹** | 填一个目录路径批量扫描(**只读**,不会移动、改名或删除你的原始档案)。旁边「浏览…」按钮用图形化文件夹选择器挑目录,不用手敲路径 |

导入前可以选本批合同属于哪个供应商。导入结果会显示**识别到了哪些列**
(如 `型号=E列 · 品名=A列 · 单价=G列 · 起订量=未找到`),识别歪了能一眼看出问题在哪。

### 查产品

「产品查询」页支持按货号、品名、规格、材质、自定义参数搜索。
比如搜 `60CR-V` 能找出所有用这种材质的产品,搜 `测电笔` 能找出哪些套装里带测电笔。

点任意一行打开详情:货号 × 参数对比表、产品图片、交付标准与要求。

### 手工建档

合同还没到的货可以先建。「+ 新增产品」→ 填产品名和第一个货号;
之后在详情页「新增货号」加其他尺寸,可以一键复制上一个货号的参数。

**采购价的规则**:合同解析出来的价格不允许手改(改了下次导入同一份合同还会被覆盖);
手工建的货号可以直接改,每次改动都记进调价历史。

## 问一句:右下角悬浮聊天助手

页面右下角的**聊天气泡**点开就是对话窗口。它不只会查,**也会干活**。

**查东西:**

- 「电缆钳剪多少钱」
- 「哪些套装里带测电笔」
- 「最近哪些产品调过价」
- 「最便宜的螺丝刀是哪个」

**交代活儿:**

- 「帮我整理一下供应商」 —— 它会扫全部合同文件名认出供应商、判断哪些不是公司名、
  把同一家的不同写法归并,然后建档并把货号挂上去
- 「哪家供应商重复了」 —— 体检出重名、空档案
- 「把 XX 并进 YY」「给 XX 补上电话」 —— 直接改
- 「你刚才改了什么」「撤销刚才那步」 —— 翻流水、退回去

它是**多步**工作的:查一步、看结果、再决定下一步,不是猜一个查询跑一次就交差。
答案上方那排小标签就是它这一轮实际做过的事。

**数字全部来自真实查询**:模型碰不到 SQL,只能选工具、填参数;取数走真实数据库查询,
答案下方会同时显示查到的原始数据表 —— **报价请以表格里的数字为准。**

查到的表格可以点窗口右上角的**导出**,一键下载 **XLSX** 或 **CSV**
(中文文件名,CSV 带 UTF-8 BOM,Excel 打开不乱码;单次最多导出 2000 行)。

### 它改了库,怎么退回去

助手的每一笔写操作都记进流水账,而且**存的时候就把"怎么退回去"一起存了**。
改动会立刻生效(不用你逐条点确认),但:

- 答案下面会出现一张**改动卡片**,写清楚做了什么,后面挂着「撤销」按钮,点一下原样还原
- 也可以直接跟它说「撤销刚才那步」,它会自己去翻流水号执行回退
- 回退是整笔事务:要么全退回去,要么一点都不动,不会退一半

> 交不出回退方案的写操作**不允许执行** —— 这是代码里的硬约束,不是约定。

还有两道防线是给"模型会编"准备的:

- **写进档案的值必须有出处。** 联系人、电话、地址这类库里没有的信息,
  只有你在对话里明确给出才写得进去;模型自己编的会被直接拒绝(见 `lib/agent.js` 的 `verifyWriteValues`)。
- **不许谎报。** 如果它说"已撤销/已合并"但这一轮其实一个写操作都没执行,
  回答后面会自动附上更正,而不是任由它糊弄过去。

> **没配 AI 也能用。** 只要还没在设置里接入 AI,问一句会自动降级为关键词检索,
> 并明确告诉你是哪一步没配好(没开开关 / 没填地址 / 没填 Key),给一个直达设置的入口。
> 配好 AI 后才有上面那些"干活"的能力。

对话历史在页面切换、窗口开合之间都会保留,「清空」按钮随时重来。

> **本地模型注意上下文。** 用 Ollama 的话,「设置 → AI 接入 → 高级」里有个
> **本地模型上下文**,默认 16384。Ollama 自己的默认值只有 2048,
> 助手多查几步就会被截断,表现成"聊到一半忘了前面查过什么"。内存吃紧可以调到 8192。

## 数据在哪 / 怎么备份

| 目录 | 内容 |
|---|---|
| `data/sku.db` | **整个库**:产品、货号、价格、调价历史、供应商、参数 |
| `data/images/` | 产品图片原图 |
| `data/backups/` | 每次导入备份前自动留的还原点 |
| `archive/` | 已导入过的合同原件 |

### 一键备份 / 换设备

「设置 → 备份迁移」:

- **导出备份文件** → 下载一个 `.db`,**图片也打包在里面**,只需搬这一个文件
- **导入备份文件** → 选中 `.db`,先显示里面有多少数据让你确认,然后整库替换

导入前会自动把当前库另存到 `data/backups/`,导错了能捞回来。

> 备份文件**不含**任何密钥(GitHub 令牌、AI API Key 都会被剔除),
> 可以放心传给另一台设备。

### 改存储位置

「设置 → 存储位置」可以把数据目录指到别处(比如加密盘、NAS 挂载点),
用图形化文件夹选择器挑选,也能现场「新建文件夹」。保存后**需要重启程序**才生效。

也可以用环境变量临时覆盖(优先级高于界面设置):

```bash
# Windows (cmd)
set SKU_DATA_DIR=E:\加密盘\sku-data && npm start

# macOS
SKU_DATA_DIR=/Volumes/加密盘/sku-data npm start
```

## 自动更新

左下角版本徽标实时显示更新状态。有新版时点亮,**点一下徽标或「设置 → 版本更新」**
填仓库 `Drsakura/sku-manager`(公开仓库,**不用填令牌**),点「检查更新」。
有新版时点「下载并更新」,程序会自动下载、校验、切换版本并重启。

**更新只替换代码,`data/` 目录原样不动。** 数据库结构如有变化,新版本启动时
会自动增量补列,旧数据库能被直接接管。

> 若仓库改成私有,则每台机器都要在这里填一个只读令牌
> (GitHub → Settings → Developer settings → Fine-grained tokens,
> 只勾该仓库的 **Contents: Read-only**)。令牌只存本机,不进备份、不进 git。

## AI 功能(可选,默认关闭)

规则解析已经能处理绝大多数规整的合同。AI 只在**规则搞不定时**才出手:
认不出表格结构、扫描件、一行都没识别出来。**模型连不上会自动退回规则解析,不影响导入。**

「设置 → AI 接入」二选一:

### 本地模型(数据不出内网)

在自己的机器上装 [Ollama](https://ollama.com),拉一个中文能力好的模型:

```bash
ollama pull qwen2.5:14b
```

要让另一台机器连过来,启动时需监听所有网卡:

```bash
# macOS
OLLAMA_HOST=0.0.0.0 ollama serve
```

然后在设置里填地址(如 `http://192.168.1.10:11434`)。
两台机器不在同一网络时,用 [Tailscale](https://tailscale.com) 组个私有网,
填它分配的 `100.x` 地址即可 —— **不要用 frp 之类的公网隧道,Ollama 没有任何鉴权。**

### 云端接口(DeepSeek / OpenAI)

选服务商、填 API Key 即可。

> ⚠️ **云端方式会把合同全文发给第三方服务商。** 合同里通常含有采购价、
> 供应商信息,甚至客户货号和客户专属要求 —— 这些往往受保密义务约束。
> 用之前请确认公司政策允许,并核对服务商的数据留存与训练条款。
> 需要保密时请用上面的本地模型。

### 安全底线(两种方式都适用)

模型返回的每一行都会**回原文逐字校验**:货号必须在原文出现,价格必须在原文出现
且落在合理区间。对不上的行直接丢弃,不会写进库。这样即使模型看错数字
(把 ¥102.00 认成 ¥120.00),错误价格也进不来。

## 维护(发布新版本)

只有你(仓库所有者)需要看这节。

### 准备

在项目根目录建一个 `.env`(已被 gitignore,不会提交):

```
GITHUB_TOKEN=<有 repo 权限的令牌>
GITHUB_REPO=Drsakura/sku-manager
```

### 发布

```bash
# 发布前自查:只打包并列出包内文件,不推送、不改版本号
node scripts/publish.js --dry-run

# 正式发布(patch / minor / major)
npm run publish patch
```

`publish` 会自动:升版本号 → 打 tag → 打包 zip + sha256 → 推送 → 建 GitHub Release → 上传资产。

`--dry-run` 会检查包里有没有混进 `data/`、`archive/`、`.env`、`*.db`,有就直接报错退出。

> 打包只包含代码。但**它不检查你 `git commit` 了什么** ——
> 提交前用 `git status` 看一眼仍然是最有效的防线。公开仓库下,
> 误提交的数据文件会立刻全网可见,而且 git 历史删不干净。

### 版本化安装布局

客户端首次运行 `npm run onboard` 后会迁成版本化布局,自动更新依赖这个结构:

```
<安装目录>/
  current.txt          当前版本号
  versions/<版本>/     各版本代码(含 node_modules)
  data/                数据库和图片(永远在版本目录之外)
  archive/  inbox/     合同原件与收件箱
  config.json          存储路径配置
```

## 常见问题

**启动报 `Cannot find module 'better-sqlite3'`**
在该目录跑一次 `npm install`。若是从别的系统拷过来的,先删掉 `node_modules` 再装。

**Mac 上 `npm install` 报编译错误**
先装一次 Xcode 命令行工具:`xcode-select --install`

**Mac 上双击 `start.command` 没反应**
终端执行 `chmod +x start.command`。

**端口 3300 被占用**
用别的端口启动:`PORT=3400 npm start`(Windows cmd 下是 `set PORT=3400 && npm start`)。

**问一句查不到结果 / 导出按钮是灰的**
导出按钮只对**最近一次带数据表的结果**可用,先查一次、有结果表了才能导出;
查不到记录就换个关键词,或确认这个型号的合同已经导入。

**导入后一行都没识别出来**
看导入结果里的「识别结果」那行,通常是表头写法没见过。可以开 AI 兜底,
或把该合同的表头告诉我补进规则。

**PDF 解析效果差**
文字版 PDF 若表格是靠坐标排版的(没有真实表格结构),目前只能按文本行猜列,
准确率有限。扫描件走 OCR,识别出的行会标「待核对」。这类建议开 AI 兜底。
